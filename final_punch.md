## 2. BLOCKER — `intel-rapl:1` is `psys`; CPU energy is double-counted

### Evidence

`cpu_energy_measured.json` reports:

```json
"rapl_domains": 2,
"rapl_domain_names": ["intel-rapl:0", "intel-rapl:1"],
"host": { "cpu_model": "Intel(R) Core(TM) i5-8500 CPU @ 3.00GHz",
          "physical_cores": 6, "socket_count": 1, "tdp_watts": 65.0 }
```

The i5-8500 is a **single-socket** desktop part. It has exactly one package
domain. The second top-level node is `psys` — the *platform* domain, which
already contains the package. Summing them counts the CPU's energy twice.

`RAPLReader.__init__` in `scripts/rapl_utils.py` filters with:

```python
pkgs = sorted(p for p in glob.glob(os.path.join(base, "intel-rapl:*"))
              if os.path.basename(p).count(":") == 1)
```

That correctly excludes subzones (`intel-rapl:0:0` = core, `:1` = uncore,
`:2` = dram) but does nothing about a **sibling** `psys` node, which also has
exactly one colon. The docstring's promise ("top-level only ... so including
them would double-count") is defeated by a domain it never anticipated.

### Three independent confirmations

| Measurement | Reported | ÷ 2 | Sanity check |
| :--- | :---: | :---: | :--- |
| Idle power | 14.005 W | **7.00 W** | ST2 independently measured **6.734 W** idle |
| LightGBM end-to-end load | 82.78 W | **41.4 W** | 82.78 W is **above the 65 W TDP**, sustained over 12 s |
| LightGBM model-only load | 216.92 W | 108.5 W | 216.92 W is **3.3× TDP** — physically impossible |

The idle agreement with ST2 to within 0.27 W is decisive.

### Fix

In `rapl_utils.py`, read each domain's `name` file and keep only packages:

```python
for p in pkgs:
    try:
        with open(os.path.join(p, "name"), "r") as fh:
            dname = fh.read().strip()
    except OSError:
        continue
    if not dname.startswith("package-"):
        continue          # 'psys' overlaps package; 'dram'/'core'/'uncore' are subzones
    ...                   # existing readability probe + append
```

Record the resolved names (`["package-0"]`) into `rapl_domain_names` so the
audit trail shows what was actually summed. **Mirror the same change in
`measure_cpu_energy.py`**, which carries its own inline reader — the module
docstring already flags this duplication as deliberate technical debt and warns
that domain-selection logic must be kept in sync. Better: delete the inline
reader and import `RAPLReader`.

### Expected effect

CPU energy roughly halves; ratios roughly double:

| Comparison | Current (double-counted) | Expected after fix |
| :--- | :---: | :---: |
| DistilBERT ÷ LR (gross) | 69.6× | ~100–140× |
| PubMedBERT ÷ LR (gross) | 134.5× | ~200–270× |

**This is the last number in the study that moves.** After it, the energy
figures are final.

## 8. What the paper says

Three findings, all already in your data, none dependent on the remaining fixes:

1. **Strict calibration constraints can be infeasible under uncertainty.** At
   τ = 0.03, conservative upper-CI filtering returns an empty feasible set
   (`Feasible: 0` in `st8_regime_reconciled.json`). A selection framework that
   can honestly answer "nothing qualifies" is more credible than one that always
   returns a winner.

2. **In-domain statistical ties do not survive distribution shift.**
   DistilBERT ≈ PubMedBERT on PsyTAR (paired ΔAUROC CI [−0.0014, +0.0207],
   includes 0) but PubMedBERT is significantly ahead on CADEC
   (CI [+0.0097, +0.0203], excludes 0). Part of the in-domain tie is simply
   N = 1,201 versus N = 7,823 — which is *why* the OOD gate is necessary, and why
   the tie rule correctly changes no selection anywhere in the grid. Report that
   as a designed negative result, not a disappointment.

3. **Out-of-domain calibration is seed-unstable, and instability scales with
   capacity.** PubMedBERT's CADEC ECE is 0.0794 ± 0.0303 — the spread is
   comparable to the entire τ = 0.07 budget — while isotonic LR sits at
   0.0409 ± 0.0043. Point-estimate feasibility is not a safe deployment
   criterion. This is a clinical-risk finding, and it justifies machinery you
   have already built.

The energy asymmetry is a supporting measurement with a stated host dependency,
not the headline. Framed this way — constrained selection plus three honest
out-of-domain findings — the study is publishable at BMC Medical Informatics and
Decision Making or JMIR Medical Informatics. The clean three-order-of-magnitude
green result you were chasing in round 1 would not have survived review.
